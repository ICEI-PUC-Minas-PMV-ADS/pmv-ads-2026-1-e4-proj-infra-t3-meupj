# Template Padrão da Aplicação

<span style="color:red">Pré-requisitos: <a href="02-Especificação do Projeto.md"> Especificação do Projeto</a></span>, <a href="04-Projeto de Interface.md"> Projeto de Interface</a>, <a href="03-Metodologia.md"> Metodologia</a>

O layout padrão das aplicações web e mobile foi definido para privilegiar leitura rápida, execução direta das ações principais e coerência visual entre os módulos do sistema.

## Padrão Visual da Web

- cabeçalhos claros com título da tela e ações principais visíveis;
- uso recorrente de cards para KPIs, listas e agrupamento de informações;
- navegação baseada em listas com busca, filtros e paginação quando necessário;
- destaque visual para ações primárias em tom índigo;
- menus de overflow por item para ações contextuais;
- modais de confirmação para exclusões e operações destrutivas;
- páginas de documento com preview autenticado e ações de abrir/baixar PDF.

## Padrão Visual do Mobile

- navegação principal por abas autenticadas;
- telas com cabeçalhos simples, foco em toque e leitura vertical;
- listas operacionais com menus contextuais por item;
- uso de botões flutuantes para criação das entidades principais;
- modais de confirmação e menus de ação compartilhados entre clientes, pedidos e dashboard;
- diferenciação clara entre fluxo web e native no tratamento de documentos.

## Identidade Visual

A solução adota interface clara, com predominância de branco, cinza claro e acento índigo, além de badges, estados e cores auxiliares para destacar status operacionais como confirmação, atraso, alerta e exclusão.

## Responsividade e Consistência

Na aplicação web, o layout foi organizado para funcionar em desktop e mobile browser, com adaptação de busca, filtros, cards e cabeçalhos. Na aplicação mobile, os fluxos foram adaptados para navegação por toque, com ênfase em telas de lista, detalhe e formulários simplificados.

## Iconografia e Padrões de Ação

Os ícones são usados para reforçar ações recorrentes como criar, editar, excluir, buscar, abrir menu, ligar, WhatsApp e emitir documentos. O sistema também adota padrão consistente para:

- feedback de carregamento;
- mensagens de erro;
- confirmação de exclusão;
- navegação para detalhes;
- emissão contextual de documentos.

> **Pendência registrada:** se a documentação final exigir composição visual estática, esta seção pode ser complementada com capturas consolidadas das telas reais do web e do mobile.
